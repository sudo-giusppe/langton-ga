# Raw results

This directory holds the data behind the v0.1 paper snapshot. Everything except
the render PNGs and `bench.txt` is committed so that the tables and figures can
be rebuilt with `python3 scripts/make_report.py`.

Regenerate the full tree from the repository root:

```bash
cargo build --release
./scripts/run_experiments.sh
python3 scripts/make_report.py
```

`run_experiments.sh` deletes and recreates `results/`. Override the defaults
with `SEEDS="1 2 3 4 5"`, `OUT=results`, and `BIN=./target/release/langton-ga`.

## Layout

```text
baseline/       classic Langton ant validation
single/         single-population GA, weaver and balanced profiles
distributed/    sequential, panmictic, and island runs (migration 0/5/20)
portfolio/      four heterogeneous islands, no migration
gallery/        analyses, traces, and renders of the portfolio winners
README.md       this file
bench.txt       generated locally by run_experiments.sh, not committed
```

### `baseline/`

| File | Content |
|---|---|
| `classic_metrics.csv` | One-row summary of the classic rule after 120,000 steps: detected period, drift, speed, pattern match, fitness, and morphology. |
| `trace.csv` | Position and cumulative displacement, sampled every 50 steps. |
| `classic_120k.txt` | Human-readable end state and cycle summary for the classic rule. |
| `classic_12k.png`, `classic_120k.png` | Renders; ignored by Git and regenerated by the script. |

### `single/`

`{weaver,balanced}_{1..5}.csv` are per-generation histories of a single
population (`pop = 64`, `gens = 80`, `steps = 10,000`, four evaluation threads).
`*_best.txt` records the winning genome and its metrics; the matching `.log` is
the CLI transcript. The `_best.txt` block is the input used by
`make_report.py` for the convergence figures.

### `distributed/`

| Path | Content |
|---|---|
| `seq_{1..5}.csv`, `seq_{1..5}_best.txt`, `seq_{1..5}.log` | Sequential baseline: one population of 256, one thread, run one seed at a time. |
| `pan_{1..5}.csv`, `pan_{1..5}_best.txt`, `pan_{1..5}.log` | Panmictic baseline: one population of 256, four evaluation threads. |
| `m{0,5,20}_{1..5}/` | Island runs: four processes of 64 individuals, top-2 migration every 0, 5, or 20 generations. |
| `m{0,5,20}_{1..5}.log` | Combined monitor/island transcript for each replicate. |

Each `m*/` directory contains `island{1..4}.csv` (per-generation history for
one island), `telemetry.csv` (arrival-ordered monitor stream), `finals.csv`
(one row per island), `island{1..4}_best.txt`, and preview PNGs.

### `portfolio/`

Four islands with the profiles `mover,builder,weaver,balanced`, no migration,
60 generations. `island{1..4}.csv` are their histories, `finals.csv` and
`telemetry.csv` follow the distributed layout, and `run.log` is the transcript.

### `gallery/`

| File | Content |
|---|---|
| `portfolio_{1..4}.csv` | 60,000-step analysis of each portfolio winner, scored with the weaver weights. |
| `balanced_1.csv` | 60,000-step analysis of a balanced single-island winner. |
| `traj_{mover,builder,weaver,balanced}.csv` | Per-step trajectories (2,000 steps) used by the behaviour figure. |
| `*.png` | High-resolution renders; ignored by Git. |

## CSV columns

`*_best.txt` files are `key=value` text. The CSV files use these headers:

**Per-generation history** (`single/*.csv`, `distributed/*/island*.csv`,
`distributed/seq_*.csv`, `distributed/pan_*.csv`):

| Column | Meaning |
|---|---|
| `generation` | Generation index, starting at 0. |
| `best`, `mean`, `median`, `worst`, `stddev` | Fitness distribution of the evaluated population. |
| `diversity` | Genotypic diversity (normalized pairwise Hamming distance). |
| `behavioral_diversity` | Mean pairwise L1 distance between 3 × 3 neighbourhood histograms. |
| `evaluations` | Cumulative simulator evaluations. |
| `elapsed_ms` | Wall time since the run started. |
| `best_mobility`, `best_compactness`, `best_complexity`, `best_colorfulness` | Fitness components of the current best genome. |

**Monitor telemetry** (`distributed/*/telemetry.csv`,
`portfolio/telemetry.csv`):

| Column | Meaning |
|---|---|
| `arrival_ms` | Monitor receive time, in milliseconds. |
| `island` | Sender island id (1-based). |
| `gen` | Generation reported by the island. |
| `best`, `mean`, `diversity` | Fitness and diversity at that generation. |
| `evaluations` | Cumulative evaluations on that island. |
| `elapsed_ms` | Sender-local elapsed time. |

Rows are ordered by arrival, not by island or generation. That is intentional:
it exposes the asynchrony. Use `(island, gen)` to reconstruct a per-island
series.

**Final summaries** (`distributed/*/finals.csv`, `portfolio/finals.csv`):

| Column | Meaning |
|---|---|
| `island` | Island id. |
| `best` | Final best fitness. |
| `gen` | Last completed generation. |
| `elapsed_ms` | Total island wall time. |
| `messages`, `bytes` | Control traffic sent by that island (migration + telemetry). |

**Analysis** (`baseline/classic_metrics.csv`, `gallery/*.csv`): one row with
the genome, simulation budget, detected cycle, fitness components, and
morphology. See the header for the exact field order.

**Traces** (`baseline/trace.csv`, `gallery/traj_*.csv`): `step,x,y,displacement`.

## Reproducibility notes

- Single-population runs are bitwise reproducible from their seed.
- Island runs are statistically but not bitwise reproducible: the OS decides
  message arrival order.
- `demo` maps `--seed s` to island `i` as `100s + i`. The sequential and
  panmictic baselines use `s` directly, so paired comparisons use the same
  replicate index but not the same random stream.
- `bench.txt` is written by the last step of `run_experiments.sh`. It is
  machine-dependent and deliberately ignored; the paper's value is not a
  portable constant.
- PNGs under `results/` are ignored to keep the repository small. The optimized
  versions used in the paper are in `paper/figs/`.
